##### 问题一：
复杂套餐如何应用于知识图谱的？
如果 客户开通了 **A**，且在 **X 地区**,  那么 **套餐 B 打 8 折**             **规则一**
如果 客户是政企大客户,  那么 **套餐 B 打 7 折**                           **规则二**
如果 客户开通了 **C** ， 那么 **不能享受任何关于 B 的折扣**            **规则三**

```
客户 K ——开通——> 套餐 A
客户 K ——所在地区——> 地区 X
```

```
规则 R1 ——需要——> 套餐 A
规则 R1 ——需要——> 地区 X
```

```
规则 R1 ——作用于——> 套餐 B
```

```
规则 R2 ——作用于——> 套餐 B
```

```
规则 R3 ——需要——> 套餐 C
规则 R3 ——否定——> 套餐 B
```

**在知识图谱中，规则不是关系，而是节点；条件是规则指向的事实；**




##### 问题二：
**你的图谱构建 准确率（Precision） 和 完备率（Recall） 是如何测算的？ 基准测试： 针对账务系统，有没有构建专门的 抽检集？对于“非法关系”或“过时规则”，你们有没有定期的 知识清理（KG Cleaning） 机制？**

对知识图谱构建采用信息抽取评估体系，通过 Precision / Recall 量化质量；  
构建了覆盖高风险条款的 Golden Triples 作为基准测试；  
同时引入 Schema 校验、规则冲突检测、时间失效与置信度衰减机制，形成持续的 KG Cleaning 闭环，确保账务规则长期可用、可审计。




**问题三：**
**针对文档修改后，向量数据库与知识图谱是如何完成同步的，对于删除的套餐规则，知识图谱是怎么处理的？**
文档修改通过结构化 Diff 驱动向量库与知识图谱的增量同步；  
所有规则节点都绑定文档版本与条款来源；  
对于删除或替换的套餐规则，采用软删除（失效标记）而非物理删除，  
保证账务规则可追溯、可复算、可审计。
