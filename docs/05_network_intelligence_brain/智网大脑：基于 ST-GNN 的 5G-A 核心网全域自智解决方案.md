### 智网大脑：基于 ST-GNN 的 5G-A 核心网全域自智解决方案

1. **全域感知层（Perception Layer）：**
    - **数据探针：** 部署在 K8s 侧的 eBPF 探针和网元侧的 NWDAF 接口。
    - **采集维度：** 涵盖信令面（HTTP/2 成功率、时延）、数据面（UPF 吞吐、丢包率）和基础设施（CPU 频率、磁盘 I/O、Dram 延迟）。
2. **ST-GNN 认知层（Cognition Layer - 核心方案）：**
    - **数字孪生图构建：** 实时生成包含物理服务器、容器、逻辑网元的异构拓扑图。
    - **时空分析引擎：** 利用 GCN 提取拓扑关联特征，利用 TCN（时间卷积网络）提取历史流量趋势。


####  邻接矩阵构建

   邻接矩阵A的构建质量直接决定了模型能否理解通信网络的本质。在工业界，我们不会只用一个简单的 0/1 矩阵，而是通过多维加权融合的方法，将物理拓扑、业务逻辑和流量演进耦合在一起。
   
   我们要构建的不是一个矩阵，而是三个矩阵的加权融合：$A_{final} = \alpha A_{SBA} + \beta A_{Phys} + \gamma A_{Traffic^{\circ}}$
####  业务逻辑矩阵

 这是基于 5G 服务化架构（SBA）定义的。如果两个网元之间存在标准的 3GPP 接口调用，则它们具有逻辑相关性。

- **构建规则：**
    - AMF 与 SMF 之间存在 N11 接口 -> 连接。
    - SMF 与 UPF 之间存在 N4 接口 -> 连接。
    - AMF 与 AMF 之间存在 N14 接口 -> 连接。

    - **权重计算：** 根据**接口调用频率或会话上下文同步量**设定。
    - **业务价值：** 捕捉信令风暴的传播路径。

#### 物理/网络拓扑矩阵-表示链路有多远

这是基于承载网和数据中心（DC）布线的。
**构建规则：**
- 两个网元是否在同一个服务器架位（Rack）？
- 是否在同一个机房（DC）？
- 中间经过几个路由器（Hop Count）

- **权重计算：** $w_{ij} = e^{-d_{ij}},$  其中$d_{ij}$是两个节点间的**时延**（RTT）
- **业务价值：** 捕捉物理链路故障（如光缆中断）引发的级联反应

#### 用户流动/流量演进矩阵
这是最动态的维度，基于用户在地理空间上的移动规律。

- **构建规则：** 统计过去 30 天，用户从基站 A 切换到基站 B 时，背后对应的边缘 UPF 切换频率。
- **权重计算：** 使用**皮尔逊相关系数**计算两个网元历史流量波形的相关性。
- **业务价值：** 预测由于人群移动（如晚高峰从市中心回住宅区）导致的流量搬移。

通过两个具体的案例进行介绍，正相关和负相关。

场景一: $V_{3}$ ,$V_{4}$ 共同服务于某大型商务区及其周边的配套生活区。午休时间，两者的刷视频流量同时激增。**皮尔逊系数公式：**
$$
\rho_{XY} = \frac{\text{cov}(X,Y)}{\sigma_X \sigma_Y}
$$
- **结果含义：** 1 表示完全正相关；-1 表示完全负相关；0 表示无线性相关。
 
 **数据采集：假设 5 个采样点，单位：Gbps**

| 时间点   | $V_{3}$(中心区流量)$x_{i}$ | $V_{4}$(生活区流量)$y_{i}$ |
| ----- | --------------------- | --------------------- |
| 12:00 | 10                    | 5                     |
| 12:15 | 20                    | 12                    |
| 12:30 | 35                    | 18                    |
| 12:45 | 30                    | 15                    |
| 13:00 | 15                    | 8                     |
这是一个**强正相关**。在 $A_{Traffic}$矩阵中， $V_{3}$和$V_{4}$之间的边权重会非常高（接近 1）。这意味着如果 AI 发现$V_{3}$开始暴涨，它会预判 $V_{4}$ 也会在几分钟内面临同样的压力。



场景二: 早高峰期间，人们离开$V_{4}$ 住宅区，前往$V_{3}$工作区 
 
 **数据采集：假设 4 个采样点，单位：Gbps**

| 时间点   | $V_{3}$(办公区流量)$x_{i}$ | $V_{4}$(住宅区流量)$y_{i}$ |
| ----- | --------------------- | --------------------- |
| 7:30  | 5                     | 40                    |
| 08:00 | 15                    | 30                    |
| 08:30 | 35                    | 15                    |
| 09:00 | 50                    | 5                     |
|       |                       |                       |

这是一个**强负相关**。在 $A_{Traffic}$矩阵中， $V_{3}$和$V_{4}$之间的边权重会非常高（接近 -1）。这意味-当住宅区网元闲下来时，办公区网元必然会忙起来，从而提前调度计算资源从郊区机房向中心机房漂移。


特殊情况：
背景：正常天，流量$V_{4}$转移到$V_{3}$需要30分钟，而暴雨天，地铁由于人多拥挤导致进站慢、流量转移被拉长到50分钟，且波峰变平缓。
X (郊区)：【10，50，10，5】（一个陡峭的波峰）
Y (中心)： 【5，10，20，45，40，15】（一个被拉长。推后的波峰）

$$
DG(i, j) = d(i, j) + \min\left( DG(i-1, j), DG(i, j-1), DG(i-1, j-1) \right)
$$
示例：

序列 X=[1,2,3,4]，序列 Y=[1,1,2,3,3,4]

计算得到的最优路径可能包含 (0,0),(0,1),(1,2),(2,3),(2,4),(3,5)

解读：Y 的前两个 `1` 与 X 的 `1` 对齐（Y 局部拉伸）；Y 的两个 `3` 与 X 的 `3` 对齐（Y 局部拉伸）

突发事件会改变正常的流量周期模式
```
正常模式：  _/‾‾‾\_       (标准高峰)
拉伸模式：  _/‾‾‾‾‾‾\_    (事件延长高峰)
压缩模式：  _/‾\_       (事件提前结束)
```

4、将查询序列的值映射到模板时间轴
```
        for q_idx, t_idx in zip(query_indices, template_indices):

      # 2. 时间扭曲因子（局部拉伸比）
      
```
        query_indices = alignment.index1

    #  3.计算局部导数作为拉伸因子
```
        stretching_factors = []
        for i in range(1, len(query_indices)):
            if template_indices[i] != template_indices[i-1]:
                dt = template_indices[i] - template_indices[i-1]
                dq = query_indices[i] - query_indices[i-1]
                if dt > 0:
                    stretching_factors.append(dq / dt)
```
